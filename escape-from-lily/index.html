What is this ?

escape-from-lily是一款使用 C++20 和 SDL3 框架开发的 2D 逃脱游戏。该项目强调现代 C++ 标准，并采用模块化、面向对象的架构来处理游戏状态、实体渲染。

设计理念

底层逻辑

本项目几乎所有功能都进行了模块化设计。例如：对于键盘输入，他仅负责接受键盘消息，这些消息用来做什么，怎么用。他不会在意；对于日志系统，他只负责记录和保存日志，而不做其他用途…设计过程中，需要一个对象时，先定义他的抽象基类，随后派生一个具体的类，通过增添、复写和继承等方法来实现功能。

本项目由单例(singleton pattern)Game类管理场景Scene类的生命周期，创建窗口和事件的创建由单例管理。场景Scene处理来自输入系统Input的消息，并将他转换为管理对象的更新逻辑基础。

实现单例和基类

上面有提到：“本项目由单例 Game 类管理…”。在设计时，Game 管理游戏的生命周期。在初始化阶段Game::Initialize()，Game 初始化 SDL3 的各个库、spdlog 系统和创建场景；随后，Game 通过责任链将事件系统和更新指令传递给场景类；在程序退出阶段，Game 会释放自己持有的成员。以下引用了维基百科上对相关设计理念的解释。

在面向对象编程中，单例模式（英语：singleton pattern），是一种常用的创建型软件设计模式。在应用这个模式时，单例对象的类必须保证只有一个实例存在。许多时候整个系统只需要拥有一个的全局对象，这样有利于我们协调系统整体的行为。…这种方式简化了在复杂环境下的配置管理。

在面向对象程式设计里，责任链模式（英语：chain-of-responsibility pattern），是一种行为型软件设计模式，它包含了一些命令对象和一系列的处理对象。每一个处理对象决定它能处理哪些命令对象，它也知道如何将它不能处理的命令对象传递给该链中的下一个处理对象。还存在往该处理链的末尾添加新的处理对象的机制。

不过以上的解释比较抽象，通俗来说：单例模式就是当对象只需要一个且需要全局访问时，就可以将他设计为单例。在本项目中Game持有 SDL3 的窗口SDL_Window* m_window和渲染器SDL_Renderer* m_renderer。当其他对象需要用到Game的成员时，我们为了避免 Bug 希望使用相同的成员，而不是或许因为粗心使用了其他的成员。这时，Game类就适合被设计为单例模式。

接下来，为了让所有的对象都能访问到Game单例。我们需要一个基类来持有Game，也就是Object基类。可以看到，Object 持有一个成员 Game&，他引用了一个获取单例的方法。此外，他还应该包含所有类都可能会用到的方法。在本项目的设计中，我认为初始化Initialize()和清理Quit()、处理事件HandleEvents(SDL_Event)、更新数据Update()以及渲染(纹理)Render()。他们可以被派生类选择性地覆写。后续，日志系统对成员有增添，待后续再补充这一部分。

场景和实体基类

打开程序就加载所有的资源？现在内存多少钱你也知道。为了避免没有必要的资源浪费，我将一部分特定功能的行为归在一个场景内，他继承自Object类，他负责管理一个场景内的所有资源。比如：在标题界面管理标题纹理；在主场景管理一组游戏实体；在另一个场景管理另一组游戏实体。对于Scene单单继承基类是无法实现完整的功能的，为此需要增添额外的属性----世界缩放glm::vec2 m_world_scale和世界大小glm::vec2 m_world_size。前者负责将背景放大屏幕大小的整数倍，后者为方便其他对象快速的获取世界的大小而创建。在 SceneMain（基类Scene的一个派生）中这两个数值是这样初始化的。注意到了吗？其实下面我们就使用了单例m_game_instance。
