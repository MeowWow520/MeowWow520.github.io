Chapter 1: 基础知识

如果你确定你已经知道以下几个问题的其中一个，你可以跳过这一段

网易我的世界和 Java 版 Minecraft 的区别

网易我的世界分为移动端(基岩版)和 Windows 端(Java 版)，简单来说一个是在电脑上游玩的一个是在手机上游玩的。而 Java 版 Minecraft 是在电脑上游玩的。网易我的世界 Java 版只有特定几个版本可以选择(如: 1.14.3)，而在 Java 版 Minecraft 上有几乎所有可以找到的版本(远古版本、愚人节版本、快照版)。相较于 Java 版 Minecraft，网易我的世界提供的 Mod 也较少，且大多数为付费订阅机制。
这是我目前能想到的几点差别

如何查询我的电脑配置

如果你是 Windows 10/11 平台: 在任务栏右键–>>任务管理器–>>左侧标题中的“性能”；或者，Win + S 键入“设备管理器” 找到左侧处理器，显示适配器；或者，在 Windows 设置中选择 系统–>>关于。(以上基于 Windows 11，其他设备类似)
如果你是 Linux 平台: 你比我更清楚如何查询性能 我的主机和笔记本电脑均为 Windows 平台，我并不知道如何查询 Linux 平台的电脑配置。如果你使用的是 Linux 平台，本文不会对你有帮助。
如果你是 MacOS 平台: 和 Linux 平台类似，本文不会对你有帮助。

JVM 和 JRE 是什么

JVM(Java Virtual Machine) 是 Java 虚拟机的缩写，JRE(Jave Runtime Environment) 是 Java 运行环境的缩写。他们的作用会在后面提到。

什么是 Minecraft 服务器

Minecraft 服务器是提供给非内网的公网用户用于联机 Minecraft 的一个媒介，实际上单人模式下的 Minecraft 也是通过在本地开设一个功能并不全面的服务器再让本地玩家加入服务器的方式实现的。在特定情况下(卡 BUG)，你也可以在单人游戏中看到类似“断开连接”的退出服务器字样。

如果你有公网 ip 或者拥有一台轻量级云服务器(运行内存约 2GB)，开设一个 Minecraft 完全免费；如果你没有这些，实际上一些内网穿透工具也能帮助你和异地好友联机，有一些内网穿透服务器提供商甚至可以免费提供服务，即便是订阅式的服务，也大多为 1~10 RMB 每月。游玩 Minecraft 并不需要过多的带宽，在我看来 10Mbps 绰绰有余。

你的电脑能开服务器吗

我可以很确定的告诉你: 是的，大多数硬件设备，只要拥有输入输出设备(键盘，屏幕)，都能开设一个 Minecraft 服务器。如果你懂得网络技术，一个 Minecraft 服务器可以只拥有硬件基础(主板、CPU、内存和储存)和联网能力。仅仅使用 SSH 和主机联络使用 CMD 命令就能开设服务器，但我并没有使用过这种方法开设，我大多数使用的是 Windows 平台，通过图形化界面控制窗口。在我的印象中，简陋到“树莓派”都能开设 Minecraft 服务器。

虽然这个教程会提到几乎涉及 Minecraft 服务器的所有，但是我还是推荐你至少游玩过离线 Minecraft 或者正版 Minecraft。前面提到这并不是一个保姆级教程，我希望你在了解以下几个常识之后再开始动手开设服务器:

Chapter 2: 开设服务器有哪些方法

准确来说，是联机的方法。任何一个 Minecraft(以下亦会简称“MC”) 游戏都是一个服务器(除了一些远古版本)，以 26.3 为例，在“游戏菜单”–>>“世界选项”–>>“多人游戏”中打开局域网功能，MC 会在聊天框中提示: “此世界现已对局域网开放。端口号为[11404]”。如果和你连接了同一网络的设备都能通过在“多人游戏”通过添加类似 [ip:port] 的方式找到你的单人游戏。一般地，MC 的多人模式会自动寻找局域网中的 MC 服务器。你只需要等待片刻即可。如果没有找到，你可以自己在“加入服务器”中的地址栏输入 [ip:port] 来测试连接，其中 ip 是路由器(不确定的说法)分配给你的内网 ip 地址。你可以通过以下的方法查询你的 ip 地址。

如何查询 ip 地址

1、使用快捷键 Win + R；
2、键入 cmd 或者 powershell；
3、在窗口中键入 ipconfig；
4、找到关键词 IPv4。

得到 ip 地址之后，你还需要知道端口号(port)。事实上在打开局域网功能之后，MC 就会告诉你 port: 比如你可以通过重新进入“多人游戏”界面，查找“端口”；也可以找到游戏的聊天框的历史消息来获取。在本示例中 10.xx.xx.xxx:11404 就是服务器地址。

这是联机的第一个方法: 使用本地局域网来联机。优点在于: 由于是使用非公网的方案，基本不会出现网络卡顿；缺点是: 只能线下面基游玩，不过搭配上后面会介绍到的“内网穿透”也能做到远程联机。这是最简单的一个方法，如果你只需要联机原版或者 Mod 数目较少的游戏，这个方法是不二之选。然而当你的需求更多(比如想要是否允许 PVP 等功能的时候)这个方法就开始显得不是很优雅。

也就有了以下的更加“优雅”的方法: 使用基于原版的 paper、bukkit、vanilla、spigot 等服务器端搭建原版服务器；使用可以加载 Fabric(Forge) Mod 的 Fabric(Forge) 服务端；还有很多其他的服务端(比如官方出的 Realms )。等等！什么是服务端？这就要开始介绍你是怎么玩上 MC 的了......

Chapter 3: 开设服务器的条件

你可以把 MC 想象成一个购物软件，当你想要购买一件东西的时候。你要下载一个购物软件，登录你的账号，然后下单，几天之后你就能收到你买的商品了。然而当你开始仔细拆开这几个步骤，这其实和 MC 服务器运行的原理没什么区别:

如果你想要玩到 MC，你现需要下载一个程序来启动 MC；另外你不可能是无名氏，你应该在启动的时候选择使用正版登录还是离线登录；当你进入世界之后，你需要控制你的键盘来控制你的角色，对着树木按住你的鼠标左键来“撸”掉树木；当你对着树木足够长时间之后，游戏发现你“撸”掉了这棵树，就会在原地掉落一个原木。你可以把上文的“游戏”先理解为服务端。你“撸”掉一棵树不是你面前的窗口知道你“撸”掉了它，而是你告诉了你的游戏: “你‘撸’掉了它”。接下来，讲清楚 MC 如何运转会很麻烦，请你原谅我无法正确地整理语序: 单人模式下的 Minecraft 也是通过在本地开设一个功能并不全面的服务器再让本地玩家加入服务器的方式实现的，在你打开单人游戏的时候，MC 做了两件事情: 1、打开一个服务端；2、打开一个客户端。客户端负责收集你如何控制你的角色，再把它告诉服务端，让服务端相应结果。服务端回把结果再返还给客户端。二者保持着联系，完成了很多游戏逻辑。我准备了一个示例来说明这个过程:

你踩下的一个压力板想要打开一扇铁门

你控制这你的 Steve 来到了压力板上，服务器在你站到压力板上时，发现了你踩下了压力板，把压力板的状态更新为“按下”，然后服务器发现这个压力板打开了一扇铁门，于是把压力板的状态和铁门打开的消息告诉了客户端。客户端知道这个铁门应该打开，于是将铁门渲染为“开启”，没有打开的时候，你无法通过铁门，游戏会把你挡在门外。现在门开了，客户端知道你可以控制角色进入门内了，于是你能进入门内，并把你进入门内之后的坐标实时同步给服务器。这样服务器知道你来到了屋子里，而不是在门外面，它可以开始控制坐在床边的你的猫看向你。

当然了，这并不是游戏在打开铁门的瞬间，要处理的所有事情。事实上，真正的情况更加复杂，上面的一些事件可能不是 100% 的由客户端(服务端)来做。我只是想要说明下面几件事情:

你的游戏需要一个管理者来理解你想要做什么，需要一个管理者对你的行为做出相应，两个管理者需要频繁的交流。他们分别对应客户端、服务端和通信。开设服务器的条件就是主要的这几个: 你要告诉加入服务器的玩家需要下载什么样子的客户端，你要准备什么样子的服务端，以及你要告诉这些客户端怎么和你的服务端联系交流信息。

Chapter 4: 开设一个原版服务器

终于要开始真正地开设一个服务器了。接下来我们要使用基于原版的 paper、bukkit、vanilla、spigot 等服务器端搭建原版服务器。

这些服务端的区别

Paper、Spigot、Bukkit 与 Vanilla 服务端的核心区别在于是否支持插件、性能优化程度以及原版特性的保留程度。Vanilla 是官方原版，Bukkit 引入了插件系统，Spigot 基于 Bukkit 做了优化，Paper 基于 Spigot 做了性能与安全优化。如果列一个表格他是这样子的:

表4-1: 原版服务端的区别

服务端 插件支持 性能优化 原版特性保留
Vanilla ❌ 不支持 无额外优化 100% 原版
Bukkit ✅ 支持 优化极少 接近原版
Spigot ✅ 支持 (兼容 Bukkit) 有基础优化 较接近原版
Paper ✅ 支持 (兼容 Bukkit & Spigot) 深度优化 可配置

下载服务端

在这里我使用 Spigot 作为示例。
首先来到 https://getbukkit.org/download/spigot/ 下载 Spigot。官网的界面如下图所示。如果你要开设一个基于 MC 26.3 的 MC 原版服务器，你应该点击对应 26.3 同一列的 Download 按钮。等待浏览器下载完成 spigot-26.3.jar 的文件。

下载 Java

在下载之前你要注意: 不同版本的 MC 要求的 Java 版本不同。下面是这些版本对 Java 版本的需求。

某些版本的 Java 版服务器要求特定的最低 Java 版本。以下是 Minecraft 服务器的一些主要最低 Java 版本要求:

  • 从 1.12(17w13a) 开始，运行 Minecraft 服务器的最低要求是 Java 8
  • 从 1.17(21w19a) 开始，运行 Minecraft 服务器的最低要求是 Java 16
  • 从 1.18(1.18-pre2) 开始，运行 Minecraft 服务器的最低要求是 Java 17
  • 从 1.20.5(24w14a) 开始，运行 Minecraft 服务器的最低要求是 Java 21，且操作系统要求为 64 位。
  • 从 26.1(26.1-snapshot-1) 开始，运行 Minecraft 服务器的最低要求是 Java 25

请注意，旧版的 Minecraft 可以运行在较新的 Java 版本上，例如 Minecraft 1.16 可以运行在 Java 17 上，Minecraft 1.18 可以运行在 Java 20 上，反之亦然。虽然服务器可以运行在旧版本的 Java 上，但建议使用最新版本，因为新版本可能带来更好的性能、更高的安全性和更少的漏洞。

摘自 Minecraft Wiki

    这一行是为了找到你的服务器放在了哪里，如果你想要更好的管理你的服务器，你应该将他放在一个你可以找到的地方。我将他放在了 D:Games\Servers\Spigot\26.3。它在 D 盘符下的 Games 文件夹中，并且我放在了 Servers 文件夹下，你的游戏文件夹下可能不只一个 MC 服务器，会有其他的游戏如果全部堆在 Games 文件夹下，一个文件夹会有上百个杂环的文件寻找起来不是很方便。创建 Servers 文件夹，将所有的服务器源文件全部放在里面，并且我对每一个服务端的版本进行了细分这样即便是拥有 100 个服务器你也能快速地找到你想要的那一个版本。值得注意的是: 这个路径不要使用中文名称。

    实际上这一行可以被省略。大多数情况下，你会将 xxxxxx.jar 和 start.bat 放在同一个文件夹下。如果你要统一管理服务器的 start.bat 我也推荐你放在同一个文件夹下然后使用创建快捷方式的方法，将这个快捷方式放在想要的位置(比如你想要将开服的 `start.bat` 放在桌面上，你可以将快捷方式放在桌面，而不是额外编写一个 `start.bat`)。虽然你可以不写，但我推荐你写上。在很多时候你可能会遇到奇奇怪怪的错误。比如你发现你填写的参数没有问题，蛋你始终无法正确的定位到位置，这时候你打开 bat 文件，你可以轻松地看到你在的目录，你使用的 Java 版本，你的参数。这样你能定位到你是否使用了错误的 Java 版本

一个错误的示例

在这个示例中，你可以明显地看到你进入了 1.14.4 的服务器，却使用了 Java 21。这导致版本不匹配启动失败

  • 第 3 行: java -jar minecraft_server.jar --nogui

这一行是启动服务器的关键，在这里我们指定了启动 Java 的版本，也就是 Java 安装目录下的 Java.exe 程序；-jar 是 JVM 参数，在后续你可以填写更多参数来启动服务器；minecraft_server.jar 是打开的文件；--nogui 是服务器的参数。在后续的自定义篇你可以了解到更多内容。

  • 第 3 行: pause

这一个命令是冻住运行窗口在服务器崩溃的时候。有时候你打开文件，会看到一个“黑框”一闪而过。有了这个参数，你可以在程序退出时保留“黑框”，这样无论是正常运行，还是发生崩溃你都能看到发生了什么。

关于这个“黑框”还能在之后的章节看到它的介绍。这里如果运行 start.bat，你会看到下面的内容(内容进行的适当的省略): 添加 pause 会在结束后要求输入按键在关闭窗口，而不是直接关闭，这样你能看到服务器的提示–也就是下一步要做的同意 Eula 条款。

修改 server.properties

server.properties 是储存服务器所有设置的文件。

在编辑 server.properties 时，行之间的顺序可以打乱，但文件结构不能改变。每一行的等号之前的文本为变量名，用户不应该修改这些内容。等号后面为变量的值，用户可以按照规则自行编辑。以#开头的行为注释，添加、修改或移除注释行不会对游戏造成影响。

一个完整的 properties 文件内容有这些：

看到这么多想想不要害怕，实际上很多时候你只需要修改一部分即可。我列出几个常见的修改内容的含义：

  • allow-flight 是否启用飞行: 如果配置为 false，你可能在飞行的时候被踢出服务器
  • difficulty 游戏难度: 游戏的难度，配置为 peaceful、easy、normal、hard 对应原版的几个难度
  • gamemode 默认游戏模式: 加入玩家的初始模式，配置为 survival、creative、adventure、spectator 对应原版的几个模式
  • generate-structures 是否生成结构: 如果配置为 false，世界就不会生成村庄等结构
  • hardcore 是否启用硬核模式: 如果配置为 true，玩家在生成模式死亡后无法重生
  • level-seed 游戏的种子: 游戏的生成种子
  • max-players 最大玩家数量
  • max-world-size 最大世界大小
  • motd 服务器添加界面的显示内容: 见下文自定义服务器的章节
  • online-mode 是否开启正版验证: 如果配置为 false，游戏不会在玩家进入服务器时验证是否为正版登录
  • server-port 服务器监听端口: 服务器在哪个端口，见下文加入游戏章节
  • spawn-protection 出生点保护: 如果配置为 16，那么在出生点 16x16 的范围内，非管理员玩家无法破坏方块
  • white-list 是否启用白名单: 如果配置为 true，只有在白名单的玩家可以加入世界

加入服务器

现在你要尝试在本地加入服务器，为了加入原版 26.3 版本的服务器，你需要下载一个原版 26.3。并在多人游戏中选择添加服务器，地址为: [本地 IP:端口]。一般的本地 IP 可以填写“127.0.0.1”，而端口是在 server.properties 中对应 server-port 的那一项。特别地，你也可以在服务器日志中找到类似于“Starting Minecraft server on *:25565”的日志信息。这也是端口。在这里我应该填入 127.0.0.1:25565。如下图:

点击“完成”，你就能看到一个属于你的服务器了。如果开启了白名单，你要在服务器后台输入“whitelist add [player_name]”，将你自己添加到白名单，当服务器返回给你类似 “System chat: Added MeowWow520 to the whitelist”时，说明添加成功。
